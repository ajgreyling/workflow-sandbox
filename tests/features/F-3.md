# F-3: User management

Tests may run against a database that already has users. Each test uses its own surname (e.g. `Test-T3`) so its rows can be found, and checks "the top row" only straight after adding.

## F-3-T1: Home screen shows the Add user button and the users area

**Steps**
1. Open the base URL.

**Expected**
- A visible heading is shown.
- An **Add user** button is visible next to the other controls.
- Below the controls, either a users table with the columns Name and Surname or the text "No users yet." is shown.
- No errors appear in the browser console.

## F-3-T2: Add user opens the modal

**Steps**
1. Open the base URL.
2. Click **Add user**.

**Expected**
- A modal titled "Add user" is shown.
- It has labelled **Name** and **Surname** inputs, both empty, and **Save** and **Cancel** buttons.
- The Name input has focus.

## F-3-T3: Saving a valid user

**Steps**
1. Open the base URL.
2. Click **Add user**.
3. Type `  Ada  ` in Name and `  Test-T3  ` in Surname (with the spaces).
4. Click **Save**.

**Expected**
- The modal closes.
- "User Ada Test-T3 saved." is shown on the home screen.
- The top row of the users table shows Name `Ada` and Surname `Test-T3`, with no leading or trailing spaces.
- No errors appear in the browser console.

## F-3-T4: Confirmation disappears after reload, user remains

**Steps**
1. Open the base URL and add a user with Name `Grace` and Surname `Test-T4`.
2. Reload the page.

**Expected**
- The "User Grace Test-T4 saved." message is no longer shown.
- A row with Name `Grace` and Surname `Test-T4` is still in the table.

## F-3-T5: Duplicates are allowed

**Steps**
1. Open the base URL and add a user with Name `Alan` and Surname `Test-T5`.
2. Add another user with Name `Alan` and Surname `Test-T5`.

**Expected**
- The table has (at least) two more `Alan Test-T5` rows than before step 1.

## F-3-T6: Required fields are validated

**Steps**
1. Open the base URL and note the number of rows in the users table.
2. Click **Add user**, leave both inputs empty and click **Save**.
3. Type `   ` (spaces only) in Name and `Test-T6` in Surname, then click **Save**.

**Expected**
- After step 2: "Name is required" is shown under Name and "Surname is required" under Surname. The modal stays open.
- After step 3: "Name is required" is shown under Name. Surname still contains `Test-T6`. The modal stays open.
- Each error message is linked to its input (`aria-describedby`).
- After closing the modal, the number of rows is unchanged.

## F-3-T7: Names longer than 100 characters are rejected

**Steps**
1. Open the base URL and click **Add user**.
2. Type 101 `a` characters into Name and `Test-T7` into Surname, then click **Save**.

**Expected**
- Either the input stops at 100 characters and the user saves with a 100-character name, or "Name must be 100 characters or fewer" is shown under Name and the modal stays open.
- No user with a name longer than 100 characters appears in the table.

## F-3-T8: Special characters are saved and shown exactly

**Steps**
1. Open the base URL and add a user with Name `José` and Surname `O'Brien-T8`.

**Expected**
- The table shows a row with Name `José` and Surname `O'Brien-T8`, exactly as typed.

## F-3-T9: Names are shown as text, not HTML

**Steps**
1. Open the base URL and add a user with Name `<b>Bold</b>` and Surname `<img src=x onerror=alert(1)>-T9`.

**Expected**
- The confirmation message and the table show the text `<b>Bold</b>` and `<img src=x onerror=alert(1)>-T9` literally.
- No bold text, image or alert dialog appears.
- No errors appear in the browser console.

## F-3-T10: Cancel closes the modal without saving

**Steps**
1. Open the base URL and note the number of rows in the users table.
2. Click **Add user**, type `Cancel` in Name and `Test-T10` in Surname.
3. Click **Cancel**.

**Expected**
- The modal closes and no message is shown.
- The number of rows is unchanged, and there is no `Cancel Test-T10` row.
- Focus is on the **Add user** button.

## F-3-T11: Escape closes the modal without saving

**Steps**
1. Open the base URL and note the number of rows in the users table.
2. Click **Add user**, type `Escape` in Name and `Test-T11` in Surname.
3. Press **Escape**.

**Expected**

- Focus is on the **Add user** button.

## F-3-T12: Keyboard use in the modal

**Steps**
1. Open the base URL and click **Add user**.
2. Press **Tab** repeatedly, more times than there are controls in the modal.
3. Click into Name, type `Kay`, press **Tab**, type `Test-T12`, then press **Enter**.

**Expected**
- During step 2, focus never leaves the modal.
- After step 3, the modal closes and "User Kay Test-T12 saved." is shown.

## F-3-T13: Double-clicking Save stores one user

**Steps**
1. Open the base URL.
2. Click **Add user**, type `Double` in Name and `Test-T13` in Surname.
3. Double-click **Save**.

**Expected**
- Exactly one new `Double Test-T13` row is added.

## F-3-T14: Editing a user

**Steps**
1. Open the base URL and add a user with Name `Edith` and Surname `Test-T14`.
2. Click **Edit** on the `Edith Test-T14` row.
3. Change Surname to `  Test-T14-edited  ` and click **Save**.

**Expected**
- After step 2: a modal titled "Edit user" is shown, with Name `Edith` and Surname `Test-T14`.
- After step 3: the modal closes and "User Edith Test-T14-edited updated." is shown.
- The row now shows `Edith` and `Test-T14-edited` (trimmed). No `Edith Test-T14` row remains, and no other row has changed.

## F-3-T15: Edit validation and cancel

**Steps**
1. Open the base URL and add a user with Name `Val` and Surname `Test-T15`.
2. Click **Edit** on that row, clear Name and click **Save**.
3. Click **Cancel**.

**Expected**
- After step 2: "Name is required" is shown under Name and the modal stays open.
- After step 3: the modal closes, the row still shows `Val Test-T15`, and focus is on that row's **Edit** button.

## F-3-T16: Deleting a user, with confirmation

**Steps**
1. Open the base URL and add a user with Name `Del` and Surname `Test-T16`.
2. Click **Delete** on that row.
3. Click **Cancel**.
4. Click **Delete** on that row again, then click **Delete** in the dialog.

**Expected**
- After step 2: a dialog asks "Delete Del Test-T16?" with **Delete** and **Cancel** buttons.
- After step 3: the dialog closes and the row is still there.
- After step 4: the row is removed, "User Del Test-T16 deleted." is shown, and no other row has changed.

## F-3-T17: Editing or deleting a user that no longer exists

**Steps**
1. Open the base URL in tab A and add a user with Name `Gone` and Surname `Test-T17`.
2. Open the base URL in tab B and delete `Gone Test-T17`.
3. In tab A (without reloading), click **Edit** on the `Gone Test-T17` row, change Name to `Gone2` and click **Save**.
4. In tab A, add `Gone` `Test-T17b`. In tab B, reload and delete it. In tab A (without reloading), click **Delete** on it and confirm.

**Expected**
- After step 3 and step 4: "This user no longer exists." is shown, the modal or dialog closes, and the table no longer shows the deleted user.

## F-3-T18: Empty state

**Steps**
1. Open the base URL.
2. Delete every user in the table, confirming each.

**Expected**
- "No users yet." is shown in place of the table.

## F-3-T19: Users survive an app restart

**Steps**
1. Open the base URL and add a user with Name `Persist` and Surname `Test-T19`.
2. Stop the app and start it again with the start command.
3. Open the base URL.

**Expected**
- A row with `Persist Test-T19` is in the table.

## F-3-T20: Users API

**Steps**
1. Open the base URL and add a user with Name `Api` and Surname `Test-T20`.
2. Open `<base URL>/api/users`.

**Expected**
- The page shows a JSON array, and its first item has `name` `Api`, `surname` `Test-T20`, a numeric `id` and a `created_at` timestamp.

## F-3-T21: Layout on mobile, tablet and desktop

**Steps**
1. Resize the page to 375×667, open the base URL, and open and close the Add user modal and the Delete dialog.
2. Repeat at 768×1024 and at 1280×800.

**Expected**
- At each size there is no horizontal scrolling, and the Add user button, the table, the modal and the dialog are fully visible and usable.
